# 6. Logs: slog JSON, an OTel agent DaemonSet and Loki

Date: 2026-11-01
Status: Accepted

## Context

Metrics (ADR 0004) and traces (ADR 0005) say what failed and where. Logs say
why, and during an incident you want to jump between the three without copying
IDs by hand. The services printed nothing useful and no logs were collected.

## Decision

- **One JSON access log line per request.** Both services set slog's default
  handler to JSON on stdout. `metrics.Wrap` already has the route, status code,
  duration and span, so it writes the line: `route`, `method`, `code`,
  `duration_ms`, `trace_id`, `span_id`. `/healthz` is not wrapped, so probes are
  not logged. Existing `log.Fatal` calls go through the same JSON handler.
- **Loki** single binary (`deploymentMode: Monolithic`), filesystem storage, no
  persistence (an emptyDir), 48h retention enforced by the compactor, OTLP
  ingest at `loki:3100/otlp`. The chart's nginx gateway, memcached caches,
  canary and test pod are off.
- **Loki chart from `grafana-community/helm-charts`** (`loki` 20.2.1). Since
  2026-03-16 the OSS chart lives there; `grafana/loki` 7.x is now the Grafana
  Enterprise Logs chart.
- **A second collector release, `otel-agent`, as a DaemonSet** (contrib, chart
  0.178.1). The `logsCollection` preset tails `/var/log/pods` with the container
  parser and skips the agent's own logs. The `kubernetesAttributes` preset adds
  the namespace, pod, deployment and `service.name`. Logs go to Loki over
  OTLP/HTTP. The agent opens no ports.
- **Loki labels come from resource attributes.** Loki's OTLP defaults index
  `k8s_namespace_name`, `k8s_pod_name`, `service_name` and the workload names.
  The log body stays the raw JSON line.
- **Grafana correlation, both ways:**
  - Loki datasource: a derived field matches `"trace_id":"(\w+)"` in the line
    and links to the Tempo datasource.
  - Tempo datasource: `tracesToLogsV2` queries `{service_name="<service>"} |=
    "<trace id>"` within ±5m of the span. Tempo's `service.name` and Loki's
    `service_name` hold the same value (`storefront`, `checkout`).
  - Provisioned datasources expand environment variables, so the `$` in
    `${__value.raw}` is written `$$` in the values file.

## Rejected

- **Promtail or Grafana Alloy.** Another agent to learn and configure; the OTel
  Collector already runs as the trace gateway.
- **Exporting logs through the OTel SDK.** It would duplicate what stdout
  already carries, and logs from pods without the SDK (Postgres, Valkey, Argo)
  would still need an agent.
- **Parsing the JSON into OTLP attributes in the agent.** The derived-field
  regex on the raw line is enough for the trace link. Parse it when a query
  actually needs fields as labels or structured metadata.
- **Collecting only the `shop` namespace.** Platform logs are useful when
  debugging the platform itself, and Loki's 48h retention keeps the volume
  small.

## Consequences

- **The agent runs as root.** Pod log files on the node are root-owned with mode
  0640, and the chart's default user can't read them. Together with the
  `hostPath` mounts this needs an exception once the Kyverno PSS baseline policy
  lands (Stage 1).
- **`memory_limiter` is not first in the agent.** The `kubernetesAttributes`
  preset puts `k8s_attributes` ahead of it. Accepted rather than overriding the
  preset's pipeline.
- **The chart renames components.** The rendered config uses `file_log`,
  `k8s_attributes` and `otlp_http` even though the values say `filelog`,
  `k8sattributes` and `otlphttp`.
- **Exemplars mostly miss on healthy traffic**, as ADR 0005 predicted. All 4
  `POST /buy` exemplars checked pointed at traces tail sampling had dropped.
  Use exemplars from error or slow buckets, whose traces are always kept.
- **Traces sent before Tempo is ready are lost.** The gateway collector sat in
  gRPC backoff until Tempo started, and the first 20 requests left no traces.
- **Image pulls can hang.** On the first `make up` one pull on each worker hung
  for two hours (Grafana, Prometheus, the CNPG operator; the Mac may have
  slept). The kubelet pulls one image at a time, so every pod scheduled behind
  it waited, and checkout failed on the missing `shop-db-app` secret because
  CNPG never started. `systemctl restart containerd` in each kind worker
  restarted the pulls.
- **`make up` needs mise on the PATH.** In a shell without mise activated, kind,
  kubectl and helm resolve to Homebrew's versions and `cilium` is missing. Run
  `mise exec -- make up`.
- **Tempo chart.** `grafana-community/helm-charts` also publishes `tempo` 3.x, a
  successor to the deprecated `grafana/tempo` chart from ADR 0005. Not switched
  yet.
- **Verified on the live cluster** (120 requests to `POST /buy`):
  - Loki has `k8s_namespace_name`, `k8s_pod_name` and `service_name` labels, and
    `{k8s_namespace_name="shop"}` returns the JSON access lines with `trace_id`
    and `span_id`.
  - 3 of the 7 kept traces were each matched by the trace→logs query, returning
    one storefront line and one checkout line per trace.
  - The Loki and Tempo datasources are provisioned with the links above.
    Checked through the Grafana API, not clicked in the UI.
